# Xray و بازیابی کامل — نسخه 3.1.0

## ارتقا و کاربران فعلی

در مسیر نصب پنل اجرا کنید:

```sh
sudo bash upgrade.sh
```

Migration شماره 008 برای تمام حساب‌های فعلی UUID پایدار می‌سازد. تاریخ انقضا، مدت، فعال/غیرفعال بودن و مصرف فعلی حفظ می‌شوند. اجرای مجدد آپدیت UUID را تغییر نمی‌دهد. حساب‌های جدید هم از همان مسیر مدیریت کاربران، خودکار برای هر دو هسته هماهنگ می‌شوند. کاربران غیرفعال، منقضی یا دارای سهمیه تمام‌شده اجازه اتصال ندارند.

لینک VLESS/XHTTP/TLS و QR در همان صفحه دانلود پروفایل کاربر نمایش داده می‌شود. کلاینت باید XHTTP پشتیبانی کند. آدرس همان دامنه HTTPS پنل و مسیر `/zvpn-xhttp/` روی پورت SSL موجود است. گواهی فعلی Nginx استفاده می‌شود؛ پورت‌های داخلی Xray فقط روی localhost هستند.

نصب تازه آخرین انتشار پایدار رسمی Xray را با بررسی SHA256 نصب می‌کند. نسخه نصب‌شده ثبت و در ارتقا/بازیابی حفظ می‌شود. ارتقای عمدی هسته به نسخه مشخص:

```sh
sudo bash ops/install-xray.sh v26.3.27
sudo systemctl restart zvpn-panel
```

نسخه نمونه را با نسخه پایدار آزموده‌شده موردنظر جایگزین کنید.

## مصرف مشترک

IKE و Xray از یک `usage_total` و یک سقف روزانه/کل استفاده می‌کنند. اولین مصرف Xray نیز مدت حساب فعال‌نشده را شروع می‌کند. تغییر پروتکل مدت را دوباره شروع نمی‌کند. شمارنده‌های پایدار و تراکنش دیتابیس جلوی دوباره‌شماری نمونه‌ها را می‌گیرند؛ ری‌استارت مدیریت‌شده پیش از قطع اتصال مصرف را ذخیره می‌کند.

اعمال سهمیه بر اساس فاصله نمونه‌برداری پنل است؛ در این فاصله ممکن است مصرف از سقف عبور کند. خرابی ناگهانی هسته ممکن است مصرف پس از آخرین نمونه را از دست بدهد. در خطای دریافت/ثبت آمار، Xray متوقف می‌شود تا اتصال بدون محاسبه مصرف ادامه پیدا نکند.

تغییر فهرست کاربران Xray با راه‌اندازی مجدد هسته اعمال می‌شود تا اتصال فعال حساب مسدودشده هم قطع شود؛ سایر کاربران Xray برای لحظه‌ای دوباره متصل می‌شوند. محدودیت تعداد دستگاه فعلاً برای IKE اجرا می‌شود؛ تعداد ارتباط‌های XHTTP معادل دقیق تعداد دستگاه نیست و برای Xray چنین تضمینی ارائه نمی‌شود. هیچ پروتکلی تضمین عدم شناسایی یا عدم فیلتر شدن ندارد.

## بکاپ تلگرام و GitHub

تلگرام اکنون آرشیو کامل بازیابی می‌فرستد: دیتابیس، کلید رمزگذاری پنل در env، گواهی و کلیدهای فعلی CA و سرور IKE، کل پوشه Let's Encrypt، Nginx، Xray، runtime و سورس همان نسخه. اگر کلید ضروری موجود نباشد بکاپ خطا می‌دهد. گواهی تازه‌ای جایگزین گواهی موجود نمی‌شود.

در تنظیمات تلگرام می‌توانید رمز آرشیو تعیین کنید؛ آرشیو رمزدار پسوند `.zenc` دارد و از AES-256-GCM استفاده می‌کند. رمز را خارج از سرور نگه دارید. آرشیو بدون رمز هم کلید خصوصی دارد و باید خصوصی نگهداری شود. فایل‌های بزرگ به بخش‌های `.part001` و ... تقسیم می‌شوند؛ برای بازیابی همه بخش‌ها لازم‌اند. بکاپ GitHub نیز از همین snapshot کامل استفاده می‌کند، رمزگذاری قبلی خود را حفظ می‌کند و فقط به مخزن خصوصی ارسال می‌شود. فایل خصوصی وارد مخزن سورس عمومی نمی‌شود.

## بازیابی بدون دسترسی به سرور قبلی

روی سرور جایگزین Ubuntu/Debian، سورس را بگیرید و آرشیو دانلودشده از تلگرام را در مسیر خصوصی کپی کنید:

```sh
git clone https://github.com/Nullfill/ZVPN.git
cd ZVPN
sudo bash ops/restore-full-backup.sh /root/zvpn-full-backup-EXAMPLE.tar.gz --verify-only
sudo bash ops/restore-full-backup.sh /root/zvpn-full-backup-EXAMPLE.tar.gz
```

برای آرشیو رمزدار همان مسیر `.zenc` را بدهید؛ رمز به‌صورت تعاملی پرسیده می‌شود. برای چند بخش، تمام نام‌ها را به ترتیب بدهید یا از الگوی مشترک استفاده کنید:

```sh
sudo bash ops/restore-full-backup.sh /root/zvpn-full-backup-EXAMPLE.tar.gz.zenc.part*
```

ابتدا checksum فایل‌ها بررسی می‌شود؛ بازیابی پس از تأیید تعاملی، دیتابیس و نصب مقصد را جایگزین می‌کند. روی مقصدی اجرا کنید که قرار است پنل از بکاپ روی آن برگردد. سورس و نسخه ثبت‌شده از داخل آرشیو استفاده می‌شوند. گواهی‌ها، UUID، لینک کاربر و کلید رمزگذاری با همان محتوا برمی‌گردند. DNS همان دامنه را به IP جدید تغییر دهید و پورت‌های 443/TCP و 500/4500 UDP را باز کنید. دسترسی به سرور قبلی لازم نیست؛ اتصال‌های فعال دوباره برقرار می‌شوند. گواهی منقضی‌شده پس از بازیابی نیاز به تمدید معمول دارد.

برای بکاپ GitHub از `ops/restore-github.sh` استفاده کنید. مهاجرت با `ops/migrate-server.sh` همان snapshot کامل را به مقصد می‌فرستد. مصرف و تغییرات بعد از زمان snapshot در آن نیستند؛ هنگام جابه‌جایی نهایی فعالیت سرور قدیمی را متوقف و DNS را جابه‌جا کنید.

دستور مستقل مهاجرت را روی **سرور فعلی** با دسترسی root اجرا کنید:

```sh
curl -fsSL https://raw.githubusercontent.com/Nullfill/ZVPN/main/ops/migrate-server.sh -o /tmp/migrate.sh && sudo bash /tmp/migrate.sh
```

IP مقصد، پورت SSH (پیش‌فرض ۲۲) و رمز root پرسیده می‌شوند. ابزارهای همراه خودکار دریافت می‌شوند و نصب مقصد با داده‌های بکاپ جایگزین می‌شود. پس از بازیابی، DNS دامنه را به مقصد تغییر دهید؛ ابزار تا ۱۰ دقیقه منتظر تغییر می‌ماند و فعال بودن سرویس‌های مقصد را بررسی می‌کند. گواهی فعلی حفظ می‌شود و مرحله صدور گواهی جدید لازم نیست. تغییر DNS توسط خود شما انجام می‌شود؛ تشخیص DNS از resolver سرور مبدا است و انتشار جهانی ممکن است دیرتر انجام شود. مقصد نباید همان سرور مبدا باشد.

بکاپ‌های JSON قدیمی فقط واردسازی منطقی هستند؛ برای بازیابی کامل سرور از آرشیو جدید استفاده کنید. آزمون‌های این نسخه، بازسازی کاربران فعلی، حساب مصرف مشترک، حفظ بایت گواهی‌ها و اتصال XHTTP از طریق TLS/Nginx را پوشش می‌دهند.
