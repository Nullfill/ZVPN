# واسط آزمایشی Netlify برای ZVPN

مسیر اتصال: برنامه کاربر ← Netlify ← Xray فعلی سرور.

این پوشه فقط روی Netlify منتشر می‌شود؛ نصب‌کننده سرور ندارد و به سرویس‌ها، پورت‌ها یا گواهی‌های سرور دست نمی‌زند. مسیر موجود `/zvpn-xhttp/` را عبور می‌دهد؛ صفحات پنل و API مدیریت عبور داده نمی‌شوند.

## ساخت پروژه

۱. در [Netlify](https://app.netlify.com/) وارد حساب شوید و ساخت پروژه از GitHub را انتخاب کنید.

۲. مخزن `Nullfill/ZVPN` و شاخه `main` را انتخاب کنید. تنظیمات انتشار:

| گزینه | مقدار |
|---|---|
| Base directory | `deploy/netlify` |
| Build command | خالی |
| Publish directory | `public` |

۳. متغیر محیطی `TARGET_DOMAIN` را برابر `https://ike.spinbox.ir` قرار دهید. اگر دامنه پنل تغییر کرد، همین مقدار را به دامنه جدید تغییر دهید. مقدار باید فقط مبدأ HTTPS باشد؛ مسیر `/zvpn-xhttp/` را به آن اضافه نکنید. روی حساب رایگان از مقدار پیش‌فرض All scopes و All deploy contexts استفاده کنید. اگر حساب امکان محدوده‌گذاری دارد، Functions و محیط Production باید مشمول باشند.

۴. پروژه را منتشر کنید. پس از هر تغییر متغیر محیطی، دوباره Deploy کنید. توکن Netlify، رمز سرور یا UUID کاربران را در مخزن ثبت نکنید.

## آزمایش کانفیگ

ابتدا فقط یک کپی از لینک Xray فعلی یک کاربر را آزمایش کنید. برای این واسط تغییر نام دامنه به‌تنهایی کافی نیست: کانفیگ کلاینت باید padding سازگار Netlify را هم داشته باشد. لینک فعلی کاربر را در یک فایل خصوصی ذخیره کنید و با ابزار زیر لینک آزمایشی بسازید:

```text
node make-link.mjs INPUT_FILE PROJECT.netlify.app OUTPUT_FILE
```

UUID همان کاربر، پورت ۴۴۳، مسیر `/zvpn-xhttp/` و حالت `packet-up` باقی می‌مانند. این ابزار فقط نسخه آزمایشی را می‌سازد؛ فایل فعلی کاربر را تغییر نمی‌دهد و UUID را در خروجی ترمینال چاپ نمی‌کند. فایل ورودی و خروجی حاوی اطلاعات اتصال خصوصی‌اند و نباید داخل GitHub یا فایل‌های عمومی Netlify قرار بگیرند.

برای دامنه اختصاصی که در همین پروژه Netlify ثبت شده و DNS و گواهی معتبرش آماده است، نام آن را به‌جای `PROJECT.netlify.app` قرار دهید و گزینه `--custom-domain` را به انتهای دستور اضافه کنید. گواهی باید برای همان نام معتبر باشد؛ اعتبارسنجی TLS را خاموش نکنید.

در تست واقعی، Netlify به قالب قدیمی padding در Referer پاسخ ۴۲۹ داد. واسط، هدر `X-Relay-Padding` کلاینت آزمایشی را به قالب فعلی سرور تبدیل می‌کند؛ پاسخ سرور نیز برای همین کلاینت ترجمه می‌شود. تنظیم Xray و کانفیگ‌های مستقیم فعلی عوض نمی‌شوند. انتقال واقعی داده از این مسیر و ثبت مصرف در حساب فعلی آزمایش شده است؛ پایداری و اتصال از اینترنت هر کاربر باید جداگانه بررسی شوند. بازشدن صفحه اصلی Netlify یا دریافت پاسخ HTTP به‌تنهایی به معنی کارکرد VPN نیست.

اتصال از اینترنت مودم را جداگانه بررسی کنید؛ کارکرد از داخل VPN یا از خود سرور، اتصال مستقیم مودم به Netlify را ثابت نمی‌کند. این واسط کشور خروجی اینترنت را عوض نمی‌کند؛ خروجی همچنان سرور یا WARP انتخابی آن است. حساب و مصرف کاربر فقط در صورت استفاده از همان UUID و Xray فعلی، در مسیر حسابداری فعلی پنل قرار می‌گیرد.

Netlify برای اجرای Edge Functions و تعداد درخواست‌ها محدودیت دارد. سقف انتظار برای هدر پاسخ ۴۰ ثانیه است؛ تعداد فراخوانی مجاز به طرح حساب بستگی دارد. پایداری و هزینه استفاده عمومی باید پیش از انتشار برای همه کاربران ارزیابی شود.
